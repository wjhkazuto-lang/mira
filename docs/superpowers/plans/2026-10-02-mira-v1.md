# Mira v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 做出 Mira v1：一个运行在本机网页上的 AI 朋友。她有分层长期记忆（核心档案 + 有类型的记忆 + 原始聊天记录），会等用户说完再回、分条回复，还有一个记忆管理页。

**Architecture:** FastAPI 单进程。`chat` 负责对话编排（等待用户说完 → 检索 → 组装上下文 → DeepSeek JSON 回复 → 分条发送）；`writer`/`reflector` 是后台记忆任务，由 `scheduler` 触发。所有数据库读写都经过 `store`（SQLite 单文件）。前端是两张纯 HTML/JS 页面，通过 WebSocket 和 REST 与后端通信。

**Tech Stack:** Python 3.12（uv 管理）、FastAPI、uvicorn、openai SDK（指向 DeepSeek）、fastembed + `BAAI/bge-small-zh-v1.5`、numpy、python-dotenv、pytest + pytest-asyncio + httpx。

**Spec:** `docs/superpowers/specs/2026-10-02-mira-design.md`

## Global Constraints

- Python `>=3.12`，用 uv 管理。本机只有系统自带的 Python 3.9，**不要用它**。
- 运行依赖只有：`fastapi`、`uvicorn[standard]`、`openai`、`fastembed`、`numpy`、`python-dotenv`。开发依赖：`pytest`、`pytest-asyncio`、`httpx`。
- 服务只绑定 `127.0.0.1:8000`。
- 只有 `mira/store.py` 可以 `import sqlite3`。
- 时间一律用 `mira.clock.now()`（返回带时区的本地时间 `datetime.now().astimezone()`），存成 ISO 8601 字符串。需要时间的类都通过构造参数 `now: Callable[[], datetime]` 注入，方便测试。
- 单元测试不能访问网络：LLM 用 `mira.fakes.FakeLLM`，embedding 用 `mira.fakes.HashEmbedder`。真实模型的测试标记为 `@pytest.mark.slow`，只有设置 `RUN_SLOW=1` 时才运行。
- 用户能看到的文字（错误提示、页面、README）用中文。代码标识符用英文。
- 开源：仓库里不能出现真实的个人数据。`.env` 和 `data/` 已在 `.gitignore` 中；evals 中的对话全部虚构。
- 枚举值（多个模块共用，统一定义在 `mira/store.py`）：
  - `MEMORY_TYPES = ("fact", "person", "commitment", "pattern", "episode")`
  - `COMMITMENT_STATUSES = ("open", "done", "dropped", "overdue")`
  - `APPROACHES = ("comfort", "normal", "raise_issue", "crisis")`
- 配置默认值（spec §3.2）：`CHAT_MODEL=deepseek-v4-pro`，`BACKGROUND_MODEL=deepseek-flash`，`REFLECT_MODEL=deepseek-v4-pro`，`DEBOUNCE_SECONDS=3`，`MAX_WAIT_SECONDS=60`，`IDLE_WRITE_MINUTES=10`，`REFLECT_HOUR=4`，`RECENT_HISTORY_TOKENS=4000`，`RETRIEVE_TOP_K=8`，`CRISIS_RESOURCES=全国心理援助热线 12356；希望24热线 400-161-9995；紧急情况 120/110`，`DEEPSEEK_BASE_URL=https://api.deepseek.com`。
- token 估算：`estimate_tokens(text) = len(text)`（中文按每字 1 token 计，是偏保守的上限）。

## Review Focus

1. **空白消息或超长粘贴**：只含空格或换行的消息应被忽略（不存储、不触发回复）；粘贴几万字的长消息应能正常处理，历史记录仍按 token 上限截取。→ Task 10 `test_blank_message_ignored`。
2. **回复发到一半时刷新页面，或开着两个标签页**：断开连接后，回复仍要完整存储，刷新后能看到；两个标签页都能收到气泡；某个连接发送失败不能影响另一个。→ Task 10 `test_detached_still_stores_reply`、`test_two_outboxes_and_dead_one_removed`。
3. **用户删除了某条事件记忆，而它是某个模式的证据**：管理页和反思器都不能崩溃，失效的证据 id 直接忽略。→ Task 9 `test_dangling_evidence_ignored`、Task 12 `test_pattern_detail_filters_dangling_evidence`。
4. **模型输出脏数据**：importance 为 0 或 9、`due_at` 写成"下周五"、回复里有空字符串。这些都应该被修正（截断到合法范围、置为 None、丢弃），不能报错。→ Task 7 `test_parse_reply_drops_empty_bubbles`、Task 8 `test_dirty_fields_normalized`。
5. **服务重启后有一批没回复的消息**（上次调用失败或进程被杀）：页面加载后可以重试，重试时用数据库里那一批原始消息。→ Task 10 `test_retry_after_restart`。

### Task 5: Retriever

**Files:**
- Create: `mira/retriever.py`, `tests/test_retriever.py`

**Interfaces:**
- Consumes: `Store.list_memories`、`Store.load_vectors`、`Embedder.embed`、`textutil.bigrams`
- Produces:
  - `score(cos: float, kw: float, importance: int, age_days: float) -> float` = `0.6*max(cos,0) + 0.25*kw + 0.15*(0.5*importance/5 + 0.5*exp(-age_days/30))`
  - `keyword_score(query: str, content: str) -> float` = `|bigrams(q) ∩ bigrams(c)| / |bigrams(c)|`（content 没有二元组时为 0；上限 1）
  - `Scored(memory: Memory, score: float)`：frozen dataclass
  - `Retriever(store: Store, embedder: Embedder, now: Callable[[], datetime] = clock.now)`，方法 `search(query: str, top_k: int, types: Collection[str] | None = None) -> list[Scored]`：按分数降序，分数相同时 id 大的在前；**不**更新 last_recalled_at

候选范围（spec §5.3）：未被替代的记忆，按 types 过滤；`age_days` 按 `updated_at` 计算；如果 `episode` 的 updated_at 超过 90 天，只有它在"所有超过 90 天的 episode"中余弦相似度排进前 20，才参与打分。

### Task 8: Writer（记忆写入器）

**Files:**
- Create: `mira/prompts/writer.md`, `mira/writer.py`, `tests/test_writer.py`

**Interfaces:**
- Consumes: `Store`、`Retriever.search`、`Embedder.embed`、`LLM.complete_json`、`render`、`format_memory`、`Settings.background_model`
- Produces:
  - `WRITER_TYPES = ("fact", "person", "commitment")`
  - `WriteResult(applied: int, skipped: list[str], episode_id: int | None)`
  - `validate_ops(ops: object, store: Store) -> tuple[list[dict], list[str]]`：返回规范化后的合法操作，以及被跳过的原因（中文）
  - `Writer(store, embedder, retriever, llm, settings, now=clock.now)`，方法 `async run() -> WriteResult | None`：没有未处理的消息时返回 None，且不调用 LLM

操作规则（spec §5.4）：
| op | 字段 | 校验与规范化 |
|---|---|---|
| `add` | type, content, subject?, importance?, due_at? | type 必须在 WRITER_TYPES 中；content 去空白后不能为空；importance 转 int 后截到 1..5，缺省为 3；due_at 用 `date.fromisoformat(str(v)[:10])` 解析，失败则为 None；commitment 的 status 设为 `"open"` |
| `update` | id, content?/importance?/due_at?/subject? | id 必须存在、未被替代、未锁定，type 在 WRITER_TYPES 中 |
| `supersede` | id, new{同 add} | id 的检查同 update；执行时先 add 新记忆，再把旧记忆的 superseded_by 指向它 |
| `set_status` | id, status | id 必须是 commitment；status 只能是 open/done/dropped（锁定的记忆也允许改状态） |

`run()` 的流程：
1. 取出未处理的消息，拼成 transcript，每行格式为 `[MM-DD HH:MM] 我：…` 或 `[MM-DD HH:MM] Mira：…`
2. `related = retriever.search(transcript, 15, WRITER_TYPES)`，再加上 `open_commitments()`，去重
3. `render("writer", now=..., transcript=..., existing=<format_memory 逐行>)`
4. 调用 `llm.complete_json(purpose="writer", model=settings.background_model, ...)`，LLM 异常直接抛出
5. `validate_ops`，然后把所有需要新建或修改的文本一次性 `embed`
6. 在 `store.transaction()` 中依次：执行操作（actor="writer"，新记忆的 `source_message_ids` 为本批消息的 id）→ 写入 episode（`data["episode"]`；content 为空时跳过，并记录原因）→ `mark_processed`

**`writer.md` 必须包含的内容**：当前日期和星期（用来把"周五"换算成具体日期）；值得记和不值得记的内容（spec §5.4）；不能新增 pattern 或 episode 类型的记忆；能用 update 或 supersede 就不要新增重复的记忆；已有记忆用 `#id` 引用；输出 json，并给出完整的 json 示例（ops 列表里四种 op 各一个，加上 episode）；episode 必须写，要包含情绪基调。

### Task 10: ChatEngine（对话编排）

**Files:**
- Create: `mira/chat.py`, `tests/test_chat.py`
- Modify: `tests/conftest.py`（增加 `ManualClock`）

**Interfaces:**
- Consumes: `Store`、`Retriever.search`、`LLM`（`LLMError`、`LLMBadJSON`）、`build_chat_messages`、`parse_reply`、`Settings`
- Produces：`ChatEngine(*, store, retriever, llm, settings, persona: str, rules: str, on_activity: Callable[[], None] = lambda: None, now=clock.now, sleep=asyncio.sleep)`，提供以下方法：
  - `attach(send: Callable[[dict], Awaitable[None]]) -> None` / `detach(send) -> None`：可以同时挂多个连接；某个 send 抛异常时，把它移除，不影响其他连接
  - `async on_user_message(text: str) -> Message | None`：`text.strip()` 为空时返回 None，什么也不做
  - `async on_typing() -> None`
  - `async retry() -> None`：用 `store.last_unanswered_batch()` 找出那一批消息并重新处理；找不到时什么也不做
  - `async wait_idle() -> None`：等当前的处理任务结束（测试用）
- 发给前端的事件：`{"type":"typing"}`、`{"type":"bubble","id":int,"text":str,"created_at":iso}`、`{"type":"error","message":"Mira 暂时没连上，点重试再试一次"}`

核心逻辑（spec §4）：
- **批次**：用户消息存到当前打开的 batch_id 下（没有打开的批次就新建一个 `uuid4().hex`）。批次在**发出第一个气泡时关闭**。
- **新消息到达时**：如果处理任务正在运行就取消它。如果还没发出过气泡，沿用同一个批次（这样旧消息和新消息会合并成一批处理）；如果已经发过气泡，下一条消息开新批次。然后重新开始等待。
- **等待用户说完**：
  ```python
  while True:
      quiet_deadline = max(last_input_at, last_typing_at) + debounce
      deadline = min(quiet_deadline, batch_started_at + max_wait)
      if now() >= deadline: break
      await sleep((deadline - now()).total_seconds())
  ```
- **处理一批**：`new = messages_in_batch(b)`；`history = recent_messages(settings.recent_history_tokens, exclude_batch=b)`；查询文本 = history 最后 6 条加上 new 的内容；`memories = retriever.search(query, settings.retrieve_top_k)`，`commitments = open_commitments()`；组装上下文后调用 `llm.complete_json(purpose="chat", model=settings.chat_model, max_tokens=1000, ...)`；对用到的记忆调用 `touch_recalled`。
- **发送**：每条气泡依次执行：发 typing → `sleep(min(0.6 + 0.05*len(text), 4.0))` → 存储 assistant 消息（同一个 batch_id；第一条带 meta `{"mood_read","approach"}`）→ 发 bubble。全部发完后调用 `on_activity()`。`on_user_message` 中也要调用 `on_activity()`。
- **出错**：`LLMBadJSON` 时，`raw.strip()` 非空就把它作为唯一一条气泡（approach 记为 `"unknown"`），否则发 error 事件；`LLMError` 或 `parse_reply` 返回 None 时，发 error 事件。批次保持未回复状态，可以重试。
- **未挂载任何连接时**照常处理和存储，只是不发送事件。

### Task 11: Scheduler（后台任务调度）

**Files:**
- Create: `mira/scheduler.py`, `tests/test_scheduler.py`

**Interfaces:**
- Consumes: `Writer.run`、`Reflector.run`、`Store.unprocessed_messages`、`Store.get/set_job_last_run`
- Produces：`Scheduler(*, store, writer, reflector, settings, now=clock.now, sleep=asyncio.sleep)`，提供以下方法：
  - `notify_activity() -> None`：把 `last_activity` 更新为当前时间（初始值是构造时的时间）
  - `async startup() -> None`：有未处理的消息就运行 writer；`get_job_last_run("reflector")` 为 None 或距今超过 24 小时，就运行 reflector
  - `async tick() -> None`：空闲时间 ≥ `idle_write_minutes` 且有未处理的消息时，运行 writer；`today_at_hour = 今天 reflect_hour:00`，如果 `now >= today_at_hour` 且（上次运行为 None 或早于 `today_at_hour`），运行 reflector
  - `async run_forever(interval: float = 30) -> None`：循环执行 `tick()`，每轮之间 `sleep(interval)`
- 所有任务都在同一个 `asyncio.Lock` 下串行执行；reflector 成功后才 `set_job_last_run("reflector", now())`；任务抛出的异常用 `logging.exception` 记录，不往外抛。

`run_evals.py`：每个场景使用一个独立的 `Store(":memory:", now=固定时间)`，执行 `run` 中列出的步骤，打印每个场景"通过/失败 + 失败原因"，最后打印总通过率；有失败时退出码为 1。运行前要提醒：这会调用真实 API，约花费几分钱。
